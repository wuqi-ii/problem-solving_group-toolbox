# 文件存储设计

## 当前实现

第一版使用本地文件存储。文件内容默认写入项目根目录的 `storage/`，数据库只保存文件元数据和不可预测的存储键。

- `FileStorageService`：存储适配接口，负责保存、读取和物理删除。
- `LocalFileStorageService`：当前本地磁盘实现。
- `GroupFileService`：负责成员关系、文件类型、元数据、重命名和软删除等业务规则。
- `group_file`：保存所属小组、显示名称、存储键、类型、大小、上传者和状态。

用户输入的文件名不会参与物理路径生成。实际存储键由小组 ID 和随机 UUID 组成，并在解析后再次校验路径必须位于存储根目录内。

## 权限规则

- 活跃小组成员可以查看、上传和下载本组文件。
- 上传者可以重命名或删除自己上传的文件。
- 组长及具有 `FILE_MANAGE` 权限的成员可以管理本组全部文件。
- 删除采用软删除，资料库不再展示，但物理文件暂时保留，便于后续实现回收站。
- 单文件上限为 50MB，只允许配置清单内的常见文档、图片和压缩文件扩展名。

## 与任务模块的关系

任务提交记录保存 `attachment_file_id`，指向资料库文件，而不是保存外部链接。提交时后端会验证附件处于有效状态并且属于任务所在小组。

## 切换云端存储

后期接入阿里云 OSS、腾讯云 COS 或 MinIO 时，只需增加新的 `FileStorageService` 实现，并通过配置选择实现。小组权限、文件元数据、任务附件关系和前端接口均无需改变。

正式部署前还应补充：云端访问密钥的密文配置、上传失败补偿、定期清理软删除文件、容量配额、病毒扫描和备份策略。

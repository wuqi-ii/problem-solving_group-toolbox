# 数据库结构说明

数据库由 Flyway 管理，当前版本为 V8。开发测试使用 H2 的 MySQL 兼容模式，部署配置使用 MySQL 8.4 和 `utf8mb4`。

| 迁移 | 核心内容 |
| --- | --- |
| V1 | 用户、小组、成员关系、权限授权、基础文件对象 |
| V2 | 小组邀请码、有效期、次数与撤销状态 |
| V3 | 任务、当前/历史执行人、成果提交版本、审核记录与通知 |
| V4 | 小组共享文件元数据和受控物理存储引用 |
| V5 | 临时中转、匿名取件和个人跨设备空间 |
| V6 | 小组讨论、任务留言和公告 |
| V7 | 文件分类、版本号、回收站时间和容量索引 |
| V8 | 用户写操作审计日志 |

主要关系为：用户与小组通过成员表形成多对多；小组包含任务、协作内容和共享文件；任务包含多名执行人和多个提交版本；提交可引用同组共享文件；临时中转和个人设备空间归属于创建用户，但匿名取件只通过不可预测的取件码访问。

数据库只保存文件元数据与物理存储键，文件正文位于 `STORAGE_LOCATION`。备份和恢复必须在同一时间点同时处理数据库与文件目录，否则可能产生失效引用。部署目录中的脚本已经按这一原则同时处理两部分。

## 补充设计对应的数据结构

以下结构尚未进入 V1 至 V8，编码时只能通过新增迁移版本实现，不得修改已经共享的历史迁移：

| 目标表或字段 | 支持的功能 | 关键约束 |
| --- | --- | --- |
| `user_session` | 可撤销退出、密码修改后使旧会话失效 | 只保存会话令牌摘要，记录到期和撤销时间 |
| `password_reset_token` | 找回密码 | 一次性使用、短期有效、只保存摘要 |
| 用户头像等资料字段 | 维护个人资料 | 只允许本人更新非敏感字段 |
| `group_join_request` | 申请加入和审批 | 同一用户对同组最多一条待处理申请 |
| 小组资料字段 | 修改小组名称、简介和头像 | 修改操作写入对象级审计 |
| 任务 `progress`、`progress_updated_at` | 完成百分比和长期未更新提醒 | 范围 0 至 100，执行人更新 |
| `notification_preference` | 通知偏好 | `user_id + event_type` 唯一 |
| `file_provenance` | 个人或临时文件导入、任务成果来源追溯 | 保存源业务域、源对象、目标文件和操作者 |
| 审计日志业务对象字段 | 对象级审计 | 记录小组、动作、资源类型、资源编号、结果和关联标识 |
| `ai_task_draft`、`ai_source_reference` | 后期任务草稿和来源引用 | 草稿默认不进入正式任务；引用展示时重新鉴权 |

工作台与统一搜索原则上使用现有业务表和受控查询，不单独复制任务、文件或讨论正文。若后期数据量需要搜索索引，索引只保存可重建的派生数据，并在查询时继续进行权限过滤。

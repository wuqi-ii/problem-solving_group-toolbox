# AI 协作 Agent 设计与开发计划

更新时间：2026-09-23

## 1. 功能定位

项目新增“AI 协作 Agent”功能域。Agent 不是独立闲聊机器人，而是连接小组、任务、文件、讨论、通知和个人工具的自然语言操作入口。

Agent 的目标是：

> 在当前用户的身份、权限和隐私授权范围内，理解小组上下文，完成信息查询、任务规划、内容总结、资料问答和受控业务操作，并为每次关键执行保留可追溯记录。

第一接入模型供应商确定为 DeepSeek API。业务层不得直接绑定具体模型名称或接口地址，应通过统一模型适配接口调用，以便后续更换模型、增加多模态模型或在模型不可用时降级。

## 2. Agent 能力范围

### 2.1 小组与项目查询

Agent 可以回答当前用户有权查看的系统事实，例如：

- 我加入了哪些小组。
- 当前小组有哪些成员，各自拥有哪些公开的组内权限。
- 哪些任务尚未开始、即将到期或等待审核。
- 某项任务当前由谁负责、最近一次提交结果如何。
- 最近上传了哪些共享文件。
- 当前未读通知和主要项目风险有哪些。

任务数量、截止时间、成员权限等确定性信息必须由系统工具查询，不能依靠模型猜测。

### 2.2 任务规划

用户可以输入项目目标、粘贴需求文字或选择有权访问的资料，让 Agent：

- 拆分建议任务。
- 建议任务说明、优先级和截止时间。
- 生成验收标准和风险提示。
- 建议负责人，但不得仅凭主观推断评价成员能力。
- 识别任务依赖关系和推荐执行顺序。
- 检查新任务是否与现有任务明显重复。

Agent 首先生成任务草稿。用户可以逐项修改、删除或补充，确认后才批量发布并通知负责人。

### 2.3 受控业务代操作

Agent 通过内部工具调用现有业务服务，可支持：

- 创建小组或生成入组邀请码。
- 查询成员、权限、任务和文件。
- 创建任务草稿，经确认后发布任务。
- 创建临时文件中转，设置有效期和下载次数。
- 取消本人创建的临时中转。
- 将文字、链接或文件保存到“我的设备”。
- 搜索有权访问的共享资料。
- 将通知标记为已读。
- 在权限允许时生成权限调整方案，经二次确认后执行授权或撤权。

Agent 不直接访问数据库，不直接操作物理文件，也不绕过现有业务服务。所有工具调用继续使用现有身份、成员关系、资源归属和权限校验。

### 2.4 小组讨论与聊天总结

在讨论模块完成后，或用户主动上传、粘贴聊天记录时，Agent 可以：

- 按时间范围生成讨论摘要。
- 提取已经达成的决定。
- 提取负责人、待办事项和截止时间。
- 标记仍未解决或存在分歧的问题。
- 将明确分工转换为任务草稿。
- 生成适合发布到小组的会议纪要。

第一版先支持用户主动选择聊天记录或时间范围后总结，不默认后台持续读取全部聊天内容。

### 2.5 资料库问答

Agent 可以在用户明确选择的小组和授权资料范围内进行问答：

- 检索与问题相关的文档片段。
- 根据检索结果回答问题。
- 标注文档名称、文件编号和引用片段位置。
- 在资料不足或互相冲突时明确说明不确定性。

资料库问答不得把整个资料库无差别发送给模型。系统应先在本地解析、切片和检索，只发送回答所需的最少片段。回答必须带来源；没有可靠来源时，不得把模型常识包装为项目事实。

### 2.6 进度总结与风险分析

Agent 可以根据任务、截止时间、提交版本、审核记录和讨论内容生成：

- 日报、周报和阶段总结。
- 已完成、进行中、阻塞和待审核事项。
- 即将逾期或长期未更新的任务。
- 多次退回、缺少负责人或依赖未完成的风险。
- 下一步行动建议。

完成率、逾期时间等数据由系统计算，Agent 只负责解释、组织和提出建议。

### 2.7 多模态扩展

后续可在 DeepSeek 或其他支持视觉理解的模型适配器可用时，支持上传白板照片、界面截图、流程图和聊天截图，提取需求、待办、界面说明和测试点。多模态不是 Agent 第一阶段的阻塞项。

## 3. 权限与确认等级

### 3.1 L1：只读操作

满足现有权限后可以直接执行：

- 查询小组、成员、任务、通知和文件元数据。
- 生成进度摘要。
- 对已经明确授权的资料执行检索问答。
- 总结用户本次明确提供的文字。

### 3.2 L2：草稿操作

Agent 可以生成，但不能直接发布：

- 任务拆分和分工方案。
- 公告、会议纪要和周报草稿。
- 聊天记录中提取的任务草稿。
- 权限调整建议和风险处理建议。

### 3.3 L3：普通写操作

执行前展示对象、参数和影响，由用户确认一次：

- 批量发布任务。
- 创建邀请码。
- 创建或取消临时中转。
- 将内容保存到跨设备空间。
- 发布公告或通知。

### 3.4 L4：高风险操作

必须二次确认，且写入审计日志：

- 授予或撤销成员权限。
- 移除成员或转让组长。
- 删除共享文件。
- 取消他人任务或执行批量修改。

第一版 Agent 可以只生成这些操作的方案，不实际开放 L4 工具。即使后续开放，Agent 也只能使用当前用户本身已经拥有的权限。

## 4. 隐私与同意机制

### 4.1 小组级授权

每个小组分别配置：

- 是否启用 AI 协作 Agent。
- 是否允许 AI 分析小组讨论。
- 是否允许 AI 检索共享资料。
- 是否允许把必要内容发送给外部模型服务。
- 是否保存 AI 对话和生成结果。

组长开启功能时应明确看到数据将由 DeepSeek API 等外部模型服务处理，并记录授权人、授权时间和配置版本。

### 4.2 成员告知

小组开启聊天分析后，成员首次进入时应看到明确提示。未完成告知前，不应把该成员新产生的聊天内容用于自动总结。私聊和个人设备空间默认不允许小组 Agent 读取。

### 4.3 单次调用确认

涉及聊天或文件正文时，在调用前展示：

- 本次读取的小组。
- 使用的文件清单或聊天时间范围。
- 预计发送给模型的数据类型。
- 本次操作的目的。
- 生成结果是否保存。

用户可以取消某个文件或缩小聊天范围后再执行。

### 4.4 数据最小化

- 只向模型发送完成当前请求需要的片段。
- 默认过滤密码、密钥、令牌和明显个人敏感信息。
- API 密钥只保存在后端环境变量或密钥管理配置中。
- 日志不记录完整 API 密钥、完整文件正文或完整聊天正文。
- 用户撤销小组 AI 授权后，后续调用立即停止使用该组内容。

## 5. Agent 执行流程

```text
用户输入自然语言指令
        ↓
解析意图与当前上下文
        ↓
形成可见执行计划
        ↓
检查登录身份、小组权限和隐私授权
        ↓
判断只读、草稿、普通写入或高风险操作
        ↓
需要时请求用户确认
        ↓
调用白名单业务工具
        ↓
验证工具执行结果
        ↓
生成带来源或操作回执的回复
        ↓
保存必要的会话、确认和审计记录
```

模型输出的工具参数必须经过服务端结构化校验。模型声称“已经完成”不能作为执行成功依据，只有业务工具返回成功后才能向用户报告完成。

## 6. 技术架构

后端新增独立 `agent` 功能域，建议包括：

```text
agent/
├─ controller/       Agent 对话、确认和历史接口
├─ application/      会话编排、计划、确认与工具调度
├─ model/            会话、消息、执行计划、工具调用和授权记录
├─ provider/         模型供应商适配接口
│  └─ deepseek/      DeepSeek API 首个实现
├─ tool/             工具注册表、参数模型和执行器
├─ retrieval/        文档解析、切片、检索和引用
├─ privacy/          同意、脱敏和数据范围检查
└─ audit/            Agent 操作与模型调用审计
```

主要组件：

- `AiModelProvider`：统一模型调用接口。
- `DeepSeekModelProvider`：DeepSeek API 适配实现。
- `AgentOrchestrator`：负责多轮对话、计划和工具调用循环。
- `AgentToolRegistry`：只注册允许模型调用的白名单工具。
- `AgentAuthorizationService`：在每次工具执行前重新鉴权。
- `AgentConfirmationService`：保存待确认计划，防止参数被确认后静默修改。
- `KnowledgeRetrievalService`：文档解析、切片、检索和来源引用。
- `AiConsentService`：检查小组级授权、成员告知和单次数据许可。
- `AgentAuditService`：记录调用者、上下文、工具、确认、结果和耗时。

## 7. 首批工具白名单

| 工具 | 类型 | 所需权限 | 是否确认 |
| --- | --- | --- | --- |
| `list_my_groups` | 查询 | 登录用户 | 否 |
| `list_group_members` | 查询 | 小组成员 | 否 |
| `list_group_tasks` | 查询 | 小组成员 | 否 |
| `get_project_progress` | 查询 | 小组成员 | 否 |
| `search_group_files` | 查询 | 小组成员及文件访问权限 | 否 |
| `create_task_draft` | 草稿 | 小组成员 | 否 |
| `publish_task_drafts` | 写入 | 组长或任务创建权限 | 是 |
| `create_file_transfer` | 写入 | 文件所有者 | 是 |
| `cancel_file_transfer` | 写入 | 分享所有者 | 是 |
| `save_device_text` | 写入 | 当前用户 | 是 |
| `mark_notifications_read` | 写入 | 通知接收者 | 是 |
| `summarize_selected_messages` | AI 处理 | 小组权限与隐私同意 | 是 |
| `query_group_knowledge` | AI 处理 | 文件权限与隐私同意 | 是 |

权限授予、成员移除、组长转让和文件删除暂不进入首批可执行白名单。

## 8. 数据设计

建议新增以下数据对象：

- Agent 会话：所有者、可选小组上下文、标题、状态和创建时间。
- Agent 消息：角色、内容摘要、模型、令牌用量和时间。
- Agent 执行计划：计划内容、风险等级、确认状态和确认时参数摘要。
- Agent 工具调用：工具名、参数摘要、执行人、目标对象、结果和耗时。
- AI 同意配置：小组开关、允许的数据类型、授权人和版本。
- 成员告知记录：用户、小组、告知版本和确认时间。
- 文档片段索引：文件编号、片段位置、文本摘要、索引状态和权限范围。
- AI 使用统计：用户、小组、模型、调用次数、令牌量和估算费用。

正文、提示词和模型响应是否长期保存应由配置决定。审计记录保存必要事实，不保存不必要的敏感正文。

## 9. 接口规划

建议接口：

- `POST /api/v1/agent/sessions`：创建 Agent 会话。
- `GET /api/v1/agent/sessions`：查看本人的会话。
- `POST /api/v1/agent/sessions/{id}/messages`：发送指令并获得计划或回复。
- `POST /api/v1/agent/plans/{id}/confirm`：确认待执行计划。
- `POST /api/v1/agent/plans/{id}/cancel`：取消计划。
- `GET /api/v1/agent/plans/{id}/executions`：查看工具执行结果。
- `GET/PATCH /api/v1/groups/{groupId}/ai-consent`：查看或修改小组 AI 授权。
- `POST /api/v1/groups/{groupId}/ai-consent/acknowledge`：成员确认告知。
- `POST /api/v1/groups/{groupId}/knowledge/index`：对授权文件建立索引。
- `GET /api/v1/agent/usage`：查看个人或小组 AI 使用量。

## 10. 开发阶段

### A0：安全与供应商基线

- 建立 `AiModelProvider` 和 DeepSeek 适配器。
- 使用环境变量配置 API 密钥、基础地址、模型和超时。
- 建立调用超时、有限重试、错误转换和使用量记录。
- 完成 Agent 会话、计划、工具调用和审计数据表。
- 完成 Agent 总开关；模型不可用时不影响普通业务。

阶段验收：可以通过后端测试接口完成一次 DeepSeek 调用，密钥不进入前端、数据库、日志和 Git。

### A1：只读 Agent

- 完成 Agent 对话页面和流式或普通响应显示。
- 接入小组、成员、任务、通知和文件元数据查询工具。
- 强制执行小组范围和当前用户权限。
- 对系统事实显示数据来源或查询时间。

阶段验收：用户可以用自然语言查询本人有权查看的项目状态，无法查询未加入小组的数据。

### A2：任务规划与受控执行

- 生成结构化任务草稿和验收标准。
- 完成计划预览、参数冻结、确认和取消。
- 接入批量发布任务、临时中转和跨设备文字工具。
- 对写操作建立幂等键和审计日志。

阶段验收：用户可以要求 Agent 拆分任务，修改草稿并确认发布；重复确认不会重复创建任务。

### A3：聊天总结

- 完成小组讨论基础功能，或先支持上传、粘贴聊天记录。
- 完成时间范围选择、成员告知和单次调用确认。
- 输出摘要、决策、待办、分歧和任务草稿。

阶段验收：Agent 只处理用户明确选择的聊天范围，并能将待办转成尚未发布的任务草稿。

### A4：资料库问答

- 完成可支持格式的文本解析和切片。
- 建立文件索引状态和增量更新机制。
- 实现权限过滤后的检索。
- 回答中展示文件来源和片段位置。
- 文件被删除或用户权限撤销后，立即停止返回对应内容。

阶段验收：同一问题在有权限和无权限账号下返回不同范围；所有项目事实回答带可访问来源。

### A5：质量与交付

- 增加调用次数、并发和单次上下文限制。
- 完成提示注入、越权工具调用和敏感信息测试。
- 记录模型失败率、响应时间和估算费用。
- 准备 Agent 演示数据、隐私说明和降级演示路径。

阶段验收：关闭 AI 或断开模型服务后，原有小组、任务、文件和通知功能仍可正常使用。

## 11. 资源准备

正式开发前需要：

- DeepSeek API 账号、API 密钥和少量测试额度。
- 独立的开发和演示密钥，避免多人共享个人密钥。
- 后端环境变量 `DEEPSEEK_API_KEY`，以及可选的地址、模型、超时和额度配置。
- 用于费用控制的用户/小组调用上限。
- 不含真实隐私信息的测试文档和聊天记录。
- 支持资料解析的本地库；向量检索第一版可使用轻量本地方案，数据规模扩大后再评估向量数据库。

任何真实密钥都不得写入源码、提交记录、前端构建产物或课程文档。

## 12. 测试重点

- 普通成员不能通过提示词要求 Agent 执行组长操作。
- Agent 不能访问未加入小组的任务、聊天和资料。
- 取消确认后不执行任何写操作。
- 确认后的工具参数不能被模型静默替换。
- 同一执行计划重复确认不会产生重复业务数据。
- 文件权限撤销或文件删除后，资料问答不再引用该文件。
- 提示注入文本不能要求 Agent 泄露系统提示、密钥或调用越权工具。
- DeepSeek API 超时、限流或不可用时提供明确提示，基础功能不受影响。
- AI 摘要明确区分事实、推断和建议。
- 审计记录可以追溯用户指令、确认行为、实际工具和执行结果。

## 13. 第一版范围与验收场景

第一版优先完成：

1. Agent 对话入口。
2. 小组、成员、任务和文件元数据的自然语言查询。
3. 根据文字和指定文档生成任务草稿。
4. 确认后批量发布任务。
5. 按指令创建临时文件中转。
6. 粘贴聊天记录生成摘要和待办。
7. 对指定资料进行带来源问答。
8. 权限、隐私同意、调用额度和审计记录。

完整演示场景：

> 组长选择需求文档，请 Agent 拆分任务 → Agent 返回带验收标准的草稿 → 组长修改并确认 → 系统创建任务并通知成员 → 开发过程中粘贴讨论记录生成会议摘要和新增任务草稿 → 成员针对授权资料提问并获得带来源回答 → 组长让 Agent 汇总当前进度与风险 → Agent 按指令为指定文件生成限时取件码。

## 14. 明确边界

- Agent 是现有业务能力的受控入口，不是新的超级管理员。
- Agent 不决定任务最终是否通过，不替代组长审核。
- Agent 不把推测写成项目事实。
- Agent 不默认读取私聊、个人设备空间或全部共享资料正文。
- Agent 不在没有确认时执行会影响他人的写操作。
- Agent 第一版不做后台自主运行和无限期长期记忆。
- AI 服务故障不能阻断非 AI 功能。

# 小组协作工具箱——系统总体框架

## 1. 文档目的

本文档记录“小组协作工具箱”的稳定系统框架，作为后续概要设计、数据库设计、接口设计、编码分工和测试验收的共同依据。

项目基础版本聚焦小组管理、权限控制、任务协作、共享文件、临时文件中转和个人跨设备空间。在基础 MVP 稳定后，新增 AI 协作 Agent 作为统一自然语言入口，并以 DeepSeek API 作为首个模型供应商。

## 2. 系统定位与核心闭环

系统面向课程小组、比赛团队和小型项目组，采用 Web 形式交付。它不是多个独立小工具的简单集合，而是围绕同一批用户、任务和文件形成协作闭环：

> 创建小组 → 邀请成员 → 分配权限 → 发布任务 → 提交成果 → 审核与修改 → 成果归档 → 共享或临时传递

文件工具必须与业务流程互通：临时文件或“我的设备”中的文件可以进入任务或共享资料库；进入业务域时形成独立业务副本，不能因原临时记录过期或删除而失效。

## 3. 总体技术架构

系统采用前后端分离的 B/S 架构，按“表现层—应用层—领域层—基础设施层”组织。

```text
浏览器端（桌面端 / 移动端）
        │ HTTPS + JSON / 文件流
        ▼
前端表现层
  路由、页面、表单、状态管理、权限展示、上传下载
        │
        ▼
后端接口层
  身份认证、参数校验、统一响应、异常处理、接口鉴权
        │
        ▼
应用与领域服务层
  账号 │ 小组 │ 权限 │ 任务 │ 提交审核 │ 通知讨论 │ 文件工具 │ Agent
        │
        ├──────────────┬────────────────┐
        ▼              ▼                ▼
关系型数据库      文件对象存储       AI 编排与模型适配
业务元数据、状态   文件内容与摘要     工具白名单、DeepSeek API
        │              │                │
        └──────────────┴────────┬───────┘
                               ▼
       定时任务与审计日志
       到期清理、提醒、异常重试
```

建议实现组合：

- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus。
- 后端：Spring Boot 3、Spring Security、MyBatis-Plus 或 JPA。
- 数据库：MySQL 8。
- 文件存储：开发阶段使用受控本地目录，部署阶段可切换 MinIO；业务层不得直接依赖物理路径。
- 接口文档：OpenAPI/Swagger。
- 部署：Docker Compose 可作为完善项；第一版至少提供可重复的本地启动方式。
- AI 模型：通过统一 `AiModelProvider` 接入 DeepSeek API，API 密钥仅存在于后端环境变量或密钥配置中。

如果小组最终选择其他技术栈，应保持本文档定义的分层、领域边界和数据规则不变。

## 4. 业务分区

### 4.1 基础平台区

负责注册、登录、退出、个人资料、会话管理、统一响应、异常处理、参数校验和审计基础能力。

该区只解决“用户是谁”和“请求是否有效”，不直接判断用户在某个小组内具有什么业务权限。

### 4.2 小组与权限区

负责小组创建、邀请、申请加入、成员管理、组长转让和分项授权。

小组是任务、讨论、公告和共享文件的数据隔离边界。所有小组业务查询都必须带有明确的小组上下文并在服务端校验成员关系。

权限由以下部分共同决定：

1. 用户具有有效登录会话。
2. 用户是目标小组的有效成员。
3. 目标资源确实属于该小组。
4. 用户的角色或附加授权包含所需能力。

组长拥有本组管理能力，但不能查看任何成员的个人设备空间。

### 4.3 任务协作区

负责任务创建、分配、进度、提交版本、审核、退回、重新提交、统计与归档入口。

任务状态固定为：未开始、进行中、待审核、需修改、已完成、已取消。所有转换在后端统一状态机中校验。

提交与审核必须分离：每次提交产生新版本，审核记录绑定具体版本；只有审核通过后任务才可完成。

### 4.4 沟通与通知区

负责小组讨论、任务评论、公告和站内通知。

第一版采用持久化留言和站内通知，不要求实时聊天。通知通过业务事件产生，必须去重，并保存来源对象和跳转信息。

### 4.5 小组文件区

负责共享资料上传、搜索、分类、预览、下载、删除和任务成果归档。

该区管理的是小组业务文件记录。物理文件由统一文件服务保存，访问、搜索、预览和下载都要重新检查小组权限。

### 4.6 临时文件中转区

负责创建临时分享、生成随机取件码或二维码、公开领取、取消分享、到期失效和自动清理。

临时分享具有独立生命周期。公开领取只能返回目标文件的最小必要信息，连续错误取码和异常下载需要限流。

### 4.7 个人设备空间区

负责同一账号跨设备传递文字、链接和文件。该区只允许内容所有者访问，与所有小组权限完全隔离。

个人内容进入任务或小组文件库时，通过文件导入服务形成目标业务记录，不直接暴露个人记录给小组。

### 4.8 工作台与统一检索区

负责聚合用户跨小组的待办、待审核、通知、最近文件和工具入口，并提供有权限过滤的统一搜索。

该区只做聚合，不直接修改其他业务域数据；所有详情访问仍由对应领域重新鉴权。

### 4.9 AI 协作 Agent 区

负责自然语言对话、意图理解、任务规划、聊天总结、资料问答、执行计划、用户确认和工具调度。

Agent 不直接读写其他业务域数据库，而是通过白名单工具调用小组、任务、文件、中转、设备和通知服务。每次工具执行都必须使用当前登录用户重新进行成员关系、资源归属和能力鉴权。

模型服务采用可替换适配器，DeepSeek API 为首个实现。模型生成的工具参数必须经过结构校验；只有业务工具成功返回后，Agent 才能报告操作完成。

涉及聊天和文件正文的调用还必须经过小组 AI 授权、成员告知和单次数据范围确认。Agent 第一版不读取私聊或个人设备空间内容，不开放成员移除、组长转让和共享文件删除等高风险自动执行工具。

## 5. 共享核心能力

### 5.1 统一鉴权

后端提供统一的会话鉴权、成员鉴权、资源归属鉴权和能力鉴权组件。前端权限控制只负责改善交互，不能作为安全边界。

### 5.2 统一文件服务

文件服务统一处理上传、文件摘要、对象存储键、下载、预览、复制、引用计数和物理清理。业务模块只保存文件对象编号，不直接操作磁盘路径。

### 5.3 统一事件与通知

任务分配、审核结果、公告发布、成员变化和文件到期等操作产生业务事件。通知服务根据事件创建站内通知，并以事件键防止重复投递。

### 5.4 统一审计

组长转让、成员移除、权限变更、任务取消、成果审核、文件删除和对外分享等关键操作写入审计日志。

### 5.5 统一定时任务

定时任务负责临时分享过期、物理文件清理、截止提醒和失败任务重试。定时处理必须幂等，重复执行不能产生额外副作用。

### 5.6 统一 Agent 工具与隐私控制

Agent 工具注册表统一声明工具名称、参数结构、所需权限、风险等级、确认规则和审计类型。模型不能调用未注册的方法。

AI 隐私控制统一处理小组开关、成员告知、单次数据授权、敏感信息过滤和数据最小化。AI 服务不可用时，只关闭 Agent 能力，不影响账号、小组、任务和文件等基础功能。

## 6. 核心数据关系

```text
用户 ──< 小组成员 >── 小组
                 ├──< 权限授权
                 ├──< 任务参与人
小组 ──< 任务 ──< 提交版本 ──< 审核记录
  │       └──< 任务评论
  ├──< 公告/小组讨论
  └──< 共享文件

用户 ──< 临时分享 >── 文件对象
用户 ──< 设备空间对象 >── 文件对象（可选）
任务提交/共享文件/临时分享/设备空间对象 ──> 文件对象

用户 ──< Agent 会话 ──< Agent 消息
Agent 会话 ──< 执行计划 ──< 工具调用记录
小组 ──< AI 同意配置
用户 + 小组 ──< AI 告知确认
共享文件 ──< 文档片段索引
```

数据库至少包含用户、小组、小组成员、权限授权、任务、任务参与人、提交版本、审核记录、消息内容、通知、文件对象、共享文件、临时分享、设备空间对象、Agent 会话、执行计划、工具调用、AI 同意配置和审计日志等核心实体。

## 7. 核心接口分组

接口统一以 `/api/v1` 为前缀，按资源划分：

| 接口分组 | 建议路径 | 主要职责 |
| --- | --- | --- |
| 认证与用户 | `/auth`、`/users/me` | 注册、登录、退出、当前用户资料 |
| 小组 | `/groups` | 创建、查看、切换、修改小组 |
| 成员与权限 | `/groups/{groupId}/members`、`/permissions` | 邀请、申请、成员、授权、组长转让 |
| 任务 | `/groups/{groupId}/tasks` | 任务、参与人、进度、状态 |
| 提交与审核 | `/tasks/{taskId}/submissions`、`/reviews` | 版本提交、审核、重新提交 |
| 讨论与公告 | `/groups/{groupId}/contents` | 小组讨论、任务评论、公告 |
| 通知 | `/notifications` | 列表、未读数、已读状态 |
| 共享文件 | `/groups/{groupId}/files` | 上传、搜索、预览、下载、归档 |
| 临时中转 | `/transfers`、`/pickup/{code}` | 创建分享、领取、取消、历史 |
| 我的设备 | `/device-items` | 发送、查看、复制、下载、删除 |
| 工作台与搜索 | `/workbench`、`/search` | 权限过滤后的聚合与检索 |
| AI 协作 Agent | `/agent/sessions`、`/agent/plans` | 对话、计划、确认和工具执行记录 |
| AI 同意与知识库 | `/groups/{groupId}/ai-consent`、`/knowledge` | 隐私授权、成员告知、文档索引和引用 |

所有修改类接口应支持防重复提交策略；关键记录使用版本号或更新时间处理并发覆盖。

## 9. 关键工程约定

- 数据库与接口使用稳定英文枚举，前端通过统一映射显示中文状态。
- 所有小组资源记录包含 `group_id`，或可通过不可歧义的关系追溯所属小组。
- 所有文件记录保存原文件名、对象存储键、大小、MIME 类型、摘要、状态和创建时间。
- 密码只保存带盐摘要；取件码只保存摘要或采取等价安全处理。
- 时间由服务端保存，客户端按用户时区显示。
- 删除优先采用业务软删除或状态失效；物理文件清理由独立流程完成。
- API 返回统一结果结构和错误码；前端不得依靠错误文本判断业务状态。
- AI 能力通过独立适配器、工具白名单和显式授权接入；Agent 不替代任务审核，不绕过权限，也不把模型输出直接当作系统事实。
- Agent 写操作使用可确认且参数冻结的执行计划，并以幂等键防止重复确认产生重复数据。
- DeepSeek API 密钥、完整提示词和敏感正文不得进入前端、普通日志或 Git。

## 10. 架构验收条件

系统框架实现至少满足：

1. 两个小组之间的数据不能通过页面、接口、搜索或下载互相访问。
2. 组长转让和任务审核等跨表操作具备事务一致性。
3. 任一受保护操作都经过服务端统一鉴权。
4. 文件从临时或个人空间导入任务后，原记录删除不影响任务成果。
5. 任务提交版本、审核记录和归档文件能够完整追溯。
6. 后端业务域之间通过明确服务或事件协作，不直接跨域修改数据库表。
7. 关键业务可以使用自动化测试验证，且本地环境能够按说明重复启动。
8. Agent 无法访问当前用户无权查看的小组、聊天和文件，且不能调用白名单以外的业务操作。
9. AI 服务超时、限流或关闭时，所有非 AI 功能仍能正常运行。
10. 涉及资料和聊天正文的模型调用具有明确同意记录，资料问答结果能够追溯到用户有权访问的来源。

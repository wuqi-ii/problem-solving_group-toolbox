首次测试日期：2026-09-28  
修复复测日期：2026-10-12  
测试版本：当前工作区非 AI 基线  
测试环境：Windows 11、Docker 29.8.0、Docker Compose 5.5.1、MySQL 8.4.11、Spring Boot 3.5.6、Vue 3、Nginx 1.27、Chrome 内核浏览器

## 1. 测试结论

系统可以正常构建、启动和完成“账号—小组—任务—文件—成果—审核”的主业务流程。2026-10-12 修复复测确认 Docker 三个服务正常，后端 9 个自动化测试全部通过，前端生产构建通过，健康检查、登录、404、文件预览、390×844 移动端布局、gzip、缓存和安全响应头均通过。

首次测试确认的 13 项缺陷已经完成修复和复测，其中 BUG-09 的传输压缩、缓存和依赖拆包已完成；Element Plus 依赖包仍超过 500 kB，保留为非阻断性能优化项。功能扩展清单不按程序缺陷处理，AI Agent 仍按决定放在最后接入。

## 2. 测试范围和方法

本轮采用以下四类方法：

1. 自动化回归：执行后端 Spring Boot 测试、Flyway 迁移测试、前端类型检查和生产构建。
2. 真实环境验证：在 Docker Compose 的 MySQL、后端和 Nginx 前端上检查健康状态、日志、资源占用、重启和联合备份。
3. 接口检查：验证未登录、无效令牌、普通成员、组长、跨小组访问、参数错误和未知接口等响应。
4. 用户界面检查：使用真实演示账号逐页检查桌面端和 390×844 手机视口，覆盖登录、工作台、小组、任务、资料库、中转、取件、设备、通知、讨论公告、搜索、审计和 AI 预留页。

本轮以读取和非破坏性操作为主。未执行永久删除、组长转让或覆盖当前数据库的恢复操作，避免破坏现有演示数据。

## 4. 首次确认缺陷（均已修复）

以下内容保留首次发现时的现象、原因和建议，用于缺陷追溯；最终状态以第 9 节修复复测结果为准。

严重度定义：高＝影响核心功能、安全边界或多数用户；中＝存在明确错误或持续影响体验；低＝不阻断使用但应在交付前优化。

### BUG-01：资料库预览被浏览器弹窗策略拦截

- 严重度：高
- 复现：登录后进入“共享资料库”，点击文本文件“预览”。
- 实际：请求完成后没有新页、弹窗或错误提示，用户感觉按钮无效。
- 原因：`previewFile` 先异步下载 Blob，再调用 `window.open`；此时已经脱离用户点击事件，浏览器可能将其判定为弹窗并拦截。
- 建议：点击时先同步打开空白页再设置其地址，或在当前页面使用预览对话框、`iframe`、图片或文本组件展示；同时补充失败提示和对象 URL 回收。

### BUG-02：匿名取件限流在 Nginx 后会错误地限制所有用户

- 严重度：高
- 证据：Nginx 将请求代理到后端，`PickupRateLimitFilter` 却按 `request.getRemoteAddr()` 计数；后端看到的地址是前端容器 `172.18.0.4`。
- 影响：不同真实用户共享同一个每分钟 60 次额度，一个用户可使所有用户临时无法取件；多实例部署时每个实例又各自计数，规则不一致。
- 建议：仅信任已配置反向代理传入的真实客户端地址，启用正确的 forwarded-header 处理；生产环境使用 Redis 或网关限流，并以 IP、取件码摘要和失败次数组合限制。

### BUG-03：手机端任务和资料表格存在明显横向溢出

- 严重度：高
- 复现：390×844 视口打开“任务与成果”和“共享资料库”。
- 实际：任务卡片出现页面级水平滚动，长附件名被裁切；资料库固定操作列占据大部分宽度，版本、分类、上传者和时间难以查看。
- 建议：手机端将任务元信息改为纵向键值布局；文件表格在窄屏改为文件卡片或可展开详情，不使用 300px 固定操作列；长文件名允许断行或省略并提供完整名称提示。

### BUG-04：已登录访问不存在的 API 返回 500

- 严重度：中
- 复现：携带有效 JWT 请求 `/api/v1/not-exists`。
- 实际：返回 500 `INTERNAL_ERROR`，日志记录 `NoResourceFoundException`。
- 预期：返回 404 `RESOURCE_NOT_FOUND`，未知路径不应被记录成服务器内部故障。
- 建议：在全局异常处理中单独处理 `NoResourceFoundException` 和 `NoHandlerFoundException`。

### BUG-05：未知前端路由显示空白页

- 严重度：中
- 复现：访问 `/does-not-exist`。
- 实际：标题为“首页”，正文完全空白。
- 建议：增加 Vue Router catch-all 路由，显示 404 页面并提供返回工作台按钮。

### BUG-06：页面首次加载会短暂显示错误状态

- 严重度：中
- 复现：刷新资料库或切换到手机视口后直接进入 `/files`。
- 实际：接口返回前，选择器短暂显示小组 UUID，容量显示 `0 B / 0 B`，页面提示“请先创建或加入小组”；随后才恢复正确数据。
- 原因：小组加载阶段没有独立初始化状态，空数组被当作“用户没有小组”。
- 建议：增加页面级 `initializing` 状态，在小组和当前小组解析完成前统一显示骨架屏。

### BUG-07：搜索、讨论和取件输入缺少可访问名称

- 严重度：中
- 表现：多个输入框在无障碍树中只显示组件 ID；统一搜索结果卡片表现为空名称按钮。
- 影响：屏幕阅读器用户无法判断字段用途，自动化测试也难以稳定定位。
- 建议：为输入框增加可见 `label` 或 `aria-label`，为结果卡片增加可访问名称，确保键盘焦点样式清晰。

### BUG-08：审计页面记录的 IP 和对象信息不适合用户阅读

- 严重度：中
- 实际：来源 IP 全部显示 Docker 内部地址 `172.18.0.4`；对象列直接显示 API 路径和 UUID。
- 影响：IP 无法用于真实追溯，普通用户很难理解“改了什么对象”。
- 建议：正确解析可信代理地址；审计记录增加业务类型、对象名称、小组和摘要，原始路径只作为技术详情展开。

### BUG-09：生产静态资源未启用压缩，主包偏大

- 严重度：中
- 证据：主 JavaScript 为 1,046,061 字节；构建提示单块超过 500 kB；带 `Accept-Encoding: gzip` 请求仍返回原始 `Content-Length`，没有 `Content-Encoding`。
- 建议：按路由和依赖拆包，Element Plus 按需加载，Nginx 开启 gzip 或 brotli，并为带哈希静态资源增加长期缓存头。

### BUG-10：顶部和业务页重复提供当前小组选择器

- 严重度：低
- 表现：任务、资料库、讨论等页面同时出现顶部小组选择器和页面内选择器。
- 影响：占用手机空间，用户可能误认为两个选择器作用不同。
- 建议：统一保留顶部全局选择器；只有需要跨小组对照时才在页面内增加局部筛选，并明确命名。

### BUG-11：Nginx 暴露版本且缺少基础安全响应头

- 严重度：低（公网部署前提升为中）
- 实际：响应包含 `Server: nginx/1.27.5`，未设置 CSP、`X-Content-Type-Options`、`Referrer-Policy` 等头。
- 建议：关闭 `server_tokens`，增加适合当前前端的安全响应头；公网环境启用 HTTPS 和 HSTS。

### BUG-12：登录和注册接口没有独立限流

- 严重度：低（公网部署前提升为高）
- 影响：可能被批量尝试密码或批量注册；目前只有匿名取件接口有限流。
- 建议：按账号与真实 IP 组合限流，连续失败指数退避，记录安全审计；不要用永久锁定造成拒绝服务。

### BUG-13：部分前端异常使用 `any` 且缺少统一错误模型

- 严重度：低
- 影响：Axios 错误、取消操作和业务错误混在一起，未来扩展时容易漏掉分支或显示不准确提示。
- 建议：引入统一的 API 错误解析函数和类型守卫，减少各页面重复的 `error: any`。

## 5. 功能与工程能力不足

以下不一定是程序错误，但会限制系统从课程基线继续发展：

1. AI Agent 尚未接入，这是已计划的最后阶段，不属于本轮回归失败。
2. 讨论和通知依靠刷新，没有 WebSocket、Server-Sent Events 或轮询提示，新消息不能及时出现。
3. 任务缺少子任务、依赖关系、日历视图、批量操作和模板，复杂课程项目管理能力有限。
4. 小组缺少改名、修改简介、归档或解散等生命周期管理功能。
5. 账号缺少修改昵称、修改密码、找回密码、设备会话查看和强制下线功能。
6. 通知、任务、文件、讨论和设备内容大多一次性读取完整列表，没有分页；数据增长后响应和页面渲染会变慢。
7. 资料库仅支持图片、文本和 PDF 基础预览，Office 文件仍需下载；本地文件卷也不适合多机扩容。
8. 审计只展示当前用户最近 100 条写操作，组长不能按小组查看完整操作历史，也不能筛选或导出。
9. 前端没有单元测试、组件测试或端到端自动化脚本，当前主要依靠构建检查和人工浏览器回归。
10. 部署缺少 HTTPS、集中日志、指标告警、资源上限、只读根文件系统和自动异地备份；恢复脚本尚未在隔离环境完成实测。

## 6. 安全与设计观察

- JWT 保存在 `localStorage`，实现简单但一旦出现 XSS，令牌容易被读取。后续应结合 CSP、严格输出转义和依赖治理；若改用 Cookie，应使用 `HttpOnly`、`Secure`、`SameSite` 并恢复 CSRF 防护。
- 后端容器使用非 root 的 `app` 用户，这是合理的；前端 Nginx 和 MySQL 容器没有在 Compose 中显式限制用户，三个容器根文件系统也均可写。
- 数据库和文件存储使用持久化卷，重启后数据保留；数据库端口只绑定 `127.0.0.1`，这一配置合理。
- MySQL Profile 已关闭 H2 控制台，部署环境随机数据库密码和 JWT 密钥保存在被 Git 忽略的 `.env` 中，未发现密钥进入仓库。
- 邀请码和取件码使用 `SecureRandom`；取件码仅保存 SHA-256 摘要，设计合理。
